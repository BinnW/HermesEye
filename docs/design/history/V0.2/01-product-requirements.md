## 定位
Hermes 是面向个人学习和效率提升的个人助手：类似钢铁侠中的贾维斯，在理解知识、梳理问题、制定计划和推进事务时提供持续支持，成为个人能力的“外骨骼装甲”。用户决定方向、授权数据与确认行动，助手提供认知与执行支持。

HermesEye 是 Hermes 在鸿蒙设备上的交互与感知界面，将个人记录、授权的系统上下文、对话和提醒连起来。“贾维斯”描述产品愿景，不代表当前已具备持续感知、自主执行或后台常驻能力。当前实现覆盖文字记录、上下文分享、文本对话和系统提醒，智能体能力仍由用户部署的 Hermes 提供。

## 核心闭环
记录学习与行动线索 → 选择本次分享的上下文 → 与 Hermes 理解和拆解问题 → 手动创建下一步提醒 → 行动后记录与回顾。服务端自动执行属于后续集成。

## 首个工程里程碑
v0.1 已交付原生开发预览：五页应用、本地记录/会话/提醒配置、可配置 HTTP 客户端、日历与设备数据适配器、系统每日提醒，以及测试和构建产物。未确认 Hermes 部署前仅称“接口适配待联调”，不称“已经替代飞书”。服务端周期执行与推送属于下个集成里程碑，不能用手机 setInterval 冒充。

## V0.2 交互里程碑
今日 / 记录 / 助手 / 我的四个主入口。今日提供记录输入、今日记录、提醒摘要与回顾；记录按日期分组；助手展示会话、分享预览与停止等待；我的集中显示模式、数据来源和助手连接。提醒、回顾、数据来源、连接为二级页面。显示模式当前仅本次运行有效，重启跟随系统。以 [视觉基线](../../07-visual-design-V0.2.md) 为准，具体实现与差异见 [页面设计](02-design.md)。

## 数据与边界
个人记录与会话保存在应用沙箱，首版限制记录 200 条、会话 100 条，每条最长 4000 字以控制存储量。Token 首版仅驻留进程内存，重启需重填；后续用 Asset Store Kit 保存。禁用备份扩展，避免敏感会话自动备份。删除本地内容不会撤回已发送到 Hermes 的内容。Hermes 使用的模型提供商可能收到上下文，App 中明确提示。

不读取其它 App 私有数据库、聊天记录、屏幕内容。不默认采集位置/健康。读取权限与上传选择分开；选择仅作用于当次发送。日历快照仅在内存保存，刷新获取当天数据，失效后需要重新读取。

## 非功能需求
原生 ArkTS + ArkUI，Stage 模型；沿用现有 API 24 配置，待真机信息确认兼容下限。无第三方 UI 框架。网络超时可解释，禁止无限重试；仅 HTTPS 正式连接，受限的局域网 HTTP 需显式开启。主要触控目标至少 48vp；可滚动页面；系统字体；状态不仅以颜色表达。

## 待用户输入与发布门槛
