# HermesEye · 前端设计 V2.1（单屏布局与可视化）

设计起稿与确认：2026-10-17 ～ 2026-10-18。基线：[14 前端设计 V2.0](14-frontend-design-V2.0.md)（卡片化、悬浮胶囊导航、左右会话、毛玻璃材质）与 [07 视觉规范](07-visual-design-V0.2.md)；业务范围沿用 [08](08-product-requirements-V1.0.md) 与模块规格（[11](../modules/daily-plan/11-daily-plan-spec.md)、[17](../modules/projects/17-project-spec.md)、[19](../modules/reading/19-reading-spec.md)），本稿只改变呈现与操作方式。

可视评审：[单屏布局评审稿（今日聚焦）](V2.0/today-one-screen.html)（浏览器原型，非设备证据）。实施映射、验证结果与未验收范围：[21 V2 前端实施与验证](../modules/frontend/21-frontend-v2-implementation.md)。

## 1. 核心目标（用户确认的唯一目标）

**使页面保持简洁**：去掉冗长的文字罗列，用可视化图表替代；去掉冗余按钮，使用手机自带的操作逻辑；页面内容尽量保持在一个屏幕以内，需要滑动才能看到的多余内容收进胶囊与弹层，使整体布局更立体，而不是更扁平。

用户提出的四个原始问题：计数类文字罗列繁琐不直观；常驻品牌顶栏没有质感；今日页内容过多；页内返回按钮与系统侧滑返回冗余。

| 纯系统侧滑返回 | 2026-10-17 | 页面内不放返回按钮或小箭头；路由栈 `onBackPress` 已具备，读屏用户同样使用系统返回 |

## 3. 全局 chrome

### 3.1 粘性页头（两态变形）

| 项目 | 规格 |
|---|---|
| 形态 | 全宽、单行、最小高度 64vp（`page_header_height` 令牌）；Stack 顶对齐覆盖在滚动区之上 |
| 顶部态 | `bg_page` 不透明、无边框、无阴影，与页面底色融为一体，看起来就是一行页首文字 |
| 浮动态 | 滚动 yOffset > 8 触发：`glass_floating` 半透明＋ BlurStyle.Thin ＋底部分隔线（`border_subtle`）＋浅阴影（`nav_shadow`，radius 14/offsetY 2）；250ms EaseOut 过渡 |
| 控件圆角化 | 浮动态下日期变为圆角胶囊（999 半径＋`bg_surface` 底），＋、··· 恢复为圆形按钮；顶部态全部透明无容器 |
| 内容 | 今日＝日期胶囊（点按开日期弹层）＋＋＋···；项目＝标题＋＋；阅读/我的＝标题；二级路由＝单行页面/对象名（无返回控件） |
| 降级 | 实色开关下浮动态为不透明 `bg_surface`，无模糊；切换路由/标签时复位到顶部态 |

### 3.2 其他全局规则

- **无常驻品牌栏**：删除「HermesEye＋Agent 状态」顶栏；Agent 状态保留在「我的」首卡与就地反馈。
- **纯系统侧滑返回**：内容区「返回」链接与会话页「返回」按钮全部删除；会话页顶栏只留需求标题与 ···，为常态毛玻璃条（沿用会话设计稿）。
- **弹层收纳**：日期、新增、工具、详情、筛选全部走底部弹层（宽屏居中），一次一个；沿用 14 §3.1 弹层规范。
- **反馈胶囊**：操作反馈浮在胶囊导航上方，撤销是它的内联动作，不再是独立按钮行。
- **内容去重**：页头承载标题后，正文不再重复大标题；各路由页以一行副标题（`pageIntro`）开场。

## 4. 今日页（单屏）

结构自上而下：**日期页头（胶囊）→ 进度环卡 → 事项卡列表 → 添加事项**。

- **进度环＝摘要**：`ProgressType.Ring` 显示完成/总数（含日历事项），中心为大号计数；空日期显示「0 事项」。
- **芯片＝筛选**：环右侧待完成/进行中/已完成三枚芯片，显示各自数量，点按过滤列表，再点一次回到全部；选中态 soft 底＋brand 图文，触控 ≥48vp。
- **日历事项**：同样的完成框与卡片形态，元信息行为「时间 · 手机日历 · 状态」；计入进度环与芯片统计。
- **空状态**：无事项日期显示说明卡＋「添加事项」唯一主动作；筛选为空提示再点芯片回到全部。
- **工具弹层（···）**：记录进展、手机日历、历史建议、记录与日报、晚间提醒。**新增弹层（＋）**：每日事项、记录进展、独立需求。
- **撤下**：项目进展、最近在读、记录进展链接、「今日计划 ›」入口与两条计数文字；`plans` 路由并入首页。

已知差异：进度环只表达完成占比；评审稿中的「进行中」浅色弧段未实现（`Progress` 单值限制，需要自绘 Canvas），是否补做待用户决定。

## 5. 项目

- **项目卡**：标题＋目标/下一步/任务统计辅助行＋阶段完成度细进度条（6vp 线性条＋「状态 · 阶段 x/y」文字），替代原纯文字罗列。
- **项目详情**：页头承载项目名；面板内不再重复大标题，保留＋/···操作行、类型·状态行与概览/阶段/行动/复盘四分区；分区 Tab 选中态与 FilterTabs 同一语言（soft 底＋brand 图文＋Medium，未选中次文字）。

## 6. 阅读

- 书籍卡解析百分数进度渲染细进度条＋「阅读进度 xx%」；未获取进度时保留「阅读进度：尚未获取」文字行，不伪造数字。
- 其余结构（概览、逐条疑问、周期设置）沿用 V1/V2 现状，本轮不改。

## 9. 与 V2.0（14）的差异

| V2.0 | V2.1 | 不变 |
|---|---|---|
| 首页三模块：今日计划 → 项目进展 → 最近在读 | 今日单屏，只有今日计划 | 四入口导航与顺序、胶囊底栏规格 |
| 计数与占用用文字罗列 | 进度环＋芯片、进度条可视化 | 三态、重要性、来源标识 |
| 日历事项只读、不参与统计、显示占用分钟 | 日历事项可勾选、计入统计、删除占用标注 | 日历改期拒绝、实例去重、建议来源排除、状态不回写系统日历 |
| 常驻品牌顶栏＋页内返回 | 无品牌栏、极薄两态页头、纯系统侧滑 | 路由栈与返回语义、会话归属规则 |
| 我的＝状态卡＋工具入口混排 | 纯配置页 | 全部配置能力与字段、Token 安全规则 |
