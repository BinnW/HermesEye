# 阅读模块 · 自动笔记整理与疑问交互设计

更新：2026-10-11；阶段：R3 V1 本地实施。用户要求依据最新架构修改项目和阅读，暂不实现 V2。当前规格取代 R1 的 IMA 主线和 R2 的“仅设计”状态；历史决策保留在 [20](20-reading-design-record.md)。

## 1. 当前有效范围

只保留授权获取微信读书笔记、周期整理、真实阅读进度和疑问交互结果。不展示笔记/划线/想法/周总结计数，不新增周报中心，不写入 IMA。其他模块的知识库范围不因此取消。

- 业务服务保存书籍来源、采集副本、整理分批状态、问题及原操作账本；Hermes 整理与回答，官方 Hermes 不作改造。
- 客户端使用 V1 普通卡片、语义颜色、四入口与滚动页面；不实现 V2 毛玻璃、悬浮胶囊或弹层设计。
- 旧 ReadingItem、摘抄、总结及关联会话保留为历史资料，不自动构造已回答的问题，不自动上传。

## 2. 来源与进度

服务端 `WEREAD_API_KEY` 仅从进程环境读取，手机使用独立业务凭据，不能将 Hermes Token 或来源凭据混用。适配器依据微信读书技能 v1.0.4，通过固定 HTTPS gateway 获取 `/book/bookmarklist`、`/review/list/mine` 和 `/book/getprogress`；想法按 synckey 完整分页，游标停滞或超过 100 页显式失败。升级提示阻止继续调用。

书籍范围由用户填写来源 ID，最多 30 本，不自动扩大到全部书架。划线和个人想法分别标记，保留条目 ID、章节/位置及正文。范围内全部来源成功后才发布新副本；失败保留上次副本。来源中暂时缺少某条笔记不会自动删除已有个人资料。

进度固定为来源的整数 0–100 百分数：1 代表 1%，缺失为 null。采集时间及已知来源更新时间分开显示，不从笔记数量推断阅读或理解程度。

## 3. 授权与周期

必要设置：书籍 ID、1–720 小时间隔、有效 IANA 时区、采集并向 Hermes 分享的同意、周期启用/暂停。默认范围为空、未同意、周期关闭；启用要求来源和 Hermes 已配置。

业务进程每 30 秒检查持久化 nextAt，按实际经过的小时数调度，时区用于时间展示而非每日整点 cron。触发前先落盘下一次时间；重启仅检查当前到期状态，不补发多个遗漏周期。相同内容指纹不重复提交。暂停阻止后续周期，不清除已有结果、不撤销已在途请求；撤销同意后不再向 Hermes 发送新的分批请求。

本地业务进程是本模块唯一周期执行者，不同时启动手机或官方 Hermes 的第二套任务。手机退出不影响已运行的业务进程；进程停止则不执行周期。

## 4. 整理与失败恢复

长笔记按字符位置分片并保留来源 ID、类型和位置，每个分批使用稳定 operationId/独立 Need，输入不超过既有 4000 字协议上限。全批完成后才更新成功整理结果；未完成时保留并明确标识上次成功整理。这里是各分批结果的顺序集合，不宣称额外执行了全书综合分析。

采集批次持久记录 collecting/collected/failed，重启将未完成采集标记 unknown；只刷新即可查看。相同采集 ID 返回原状态，不能自动重采。操作先落业务账本再请求 Hermes。重复操作返回原回执，未知状态不重发；重启后的 submitting 转 unknown。客户端可刷新副本并查询原操作，但不能猜测已成功或自动解除未知阻塞。整理提示禁止工具和来源指令，真实工具权限仍由 Hermes 服务端配置控制，提示词不是安全隔离机制。

预览有明确容量边界：每书最多 2000 条、单条 16000 字、采集正文序列化不超过 500KB；来源分页最多 100 页；客户端响应最多 1MiB。超过边界显式失败，不截断后冒充完整结果。更大规模的分页结果 UI/归档仍需后续完善。

## 5. 疑问与交互

当前实施选择**用户在本应用明确提问**，这是本轮实施决策，未将笔记自动标记或 AI 候选问题作为用户意图。流程：查看书籍来源 → 选择条目 → 确认连续原文片段 → 输入疑问 → 明确发送。

来源片段必须属于选中原文，1–1500 字；短笔记预填原文，长笔记要求用户自行选择，不能悄悄截断。疑问及本轮输入为 1–1000 字；最终序列化输入仍须满足协议上限，超限提示缩小范围。问题保存书籍 ID、条目 ID、片段位置、原始快照、origin=user 和独立 needId；同书不同问题不共用结果。

实际完成的回答才显示回答正文；等待、unknown、not_submitted 与完成分别展示。继续讨论沿用该问题的 Need，不能自动判定“已理解”。来源更新不改写既有问题的引用快照。来源笔记和疑问每次先展示 20 条，可逐批展开；完整回答连续显示，不塞进小弹窗。

## 6. 客户端副本与页面

`ReadingPanel` 通过 `/eye/v1/reading` 读取真实书籍、策略、分批及问题结果；校验后经 Index 的原子 commit 保存到当前 Space 的 readingSnapshot。readingServerId/readingWorkspaceId 防止绑定不同服务后覆盖旧副本；请求携带发起 spaceKey，期间切换服务器禁止写入新空间。Token 仅本次连接内存使用，重新进入需连接；缓存支持离线查看。

阅读页面依次显示连接/缺失状态、真实书籍结果、必要设置和明确提问。缓存失败不覆盖旧本机副本，网络失败不自动退回兼容文本会话。采集按钮先保存当前可见的授权范围，避免沿用旧设置；暂停时不显示即将运行。历史阅读资料独立保留，旧计数退出页面。V1 交互参考见 [阅读原型](../../design/reading/index.html)，原型样例不是私人数据或验收证据。

## 7. 验证与未验收范围

覆盖来源分页/单位/升级、完整采集后发布、长笔记分片、内容去重、周期暂停/重启、历史保留、原文引用、同书问题隔离、超时不重放、HTTP 契约、身份及缓存失败。测试入口：`python3 -m unittest discover -s backend/tests -v`、`node scripts/test-ui-flows.cjs`、`bash scripts/verify.sh`、`bash scripts/device.sh test`。

实际构建及设备结果见 [05](../../testing/05-release.md)、[20](20-reading-design-record.md)。本轮未调用真实微信读书私人数据，也未将此前通用 Hermes 联调推断为本模块已联调。家庭 Ubuntu 部署、手机到业务服务网络、真实采集及服务端周期实跑仍待实际配置和验收。
