# HermesEye · 产品需求与实现索引 V1.0

更新：2026-10-01。范围依据为 [08 · 用户确认的产品需求](08-product-requirements-V1.0.md)，交互依据为 [09 · 前端设计](09-frontend-design-V1.0.md)。本文同步当前工程，不能替代 08 中的完整验收要求。V0.2 基线见 [历史文档](history/V0.2/01-product-requirements.md)。

## 定位
Hermes 是个人学习、思考与执行的助手，提供贾维斯式能力支持。HermesEye 是个人事务的统一入口，V1.0 目标为完全替代飞书作为 Hermes 交互入口；当前工程尚未达到这一验收目标。

用户从需求出发建立会话，将计划、项目、阅读、任务与成果关联起来。无明确目标时建立独立的“漫无目的”需求；单纯记录可先保存在收件箱。入口与数据可控，不要求模型推理全部本地运行。

## 主流程
今日计划 → 项目进展 → 最近在读。导航固定为今日 / 项目 / 阅读 / 我的。全局入口提供记录与发起需求；连接和录入表单不重复显示全局操作。

计划、项目、书籍进入各自的需求会话；会话支持重命名和归入项目，保留稳定标识、消息和原始来源关联。AI 回复、真实运行、成果和部署回执严格分开。

## 数据边界
Token 仅在输入内存与系统 Asset Store 中存在，普通配置仅保存别名；安全存储失败不降级为明文。模型提供商可能收到用户确认分享的上下文。HTTP 私有网络需显式允许，支持 RFC1918、回环及 Tailscale 100.64/10；不开放任意公网 HTTP。

新数据格式 version=2，保留旧文件；V0.2 全局历史迁入独立需求，旧记录与提醒完整保留在本地空间，不自动传给新服务器。当前兼容文本接口仍非流式，本机历史无旧版 100 条上限，单次发送显示“最近 40 条”；这不是服务端会话恢复方案。

## 发布门槛
真实 Hermes 协议、Tailscale 连通性、签名安装、设备权限、Asset Store 重启恢复、强提醒及深浅色/窄屏验收、服务端重启和多端同步证据齐备后，才能宣布 V1.0 完成。当前证据见 [05 · 验收记录](05-release.md)。
