# HermesEye · 产品需求 v0.1

日期：2026-09-24。状态：需求基线草案，待确认 Hermes 版本、手机版本和首批数据源。

## 定位
面向单个用户的鸿蒙原生个人秘书入口。替代飞书中与本地 Hermes 的个人对话场景，并把个人记录与授权的系统数据组合成可检查的上下文，减少截图传递。不是团队协作工具，也不在手机上重新实现智能体。

## 核心闭环
记录想法 → 查看今天的数据 → 选择本次分享的上下文 → 向 Hermes 提问 → 保存行动项 → 系统提醒 → 手动执行或后续服务端定期执行。

## 用户故事与验收
|编号|优先级|需求|验收条件|
|---|---|---|---|
|R01|P0|配置自己的 Hermes|地址与模型可保存；Token 不进入普通存储；未配置不能发送|
|R02|P0|连续文本对话|携带本地历史；显示等待、成功和失败；失败保留输入，不自动重放有副作用的请求|
|R03|P0|个人记录|创建、浏览、删除；重启后保留；空内容拒绝|
|R04|P0|系统数据|主动读取电量、系统时间；日历按需授权；拒绝权限不阻断其它页面|
|R05|P0|可控分享|发送前预览并选择记录/日历/设备数据，默认关闭；快照标注采集时间；不自动上传|
|R06|P0|每日/工作日提醒|真实调用系统代理提醒；失败不显示成功；支持取消；重启保留系统 ID|

|R10|P2|扩展数据源|位置、健康、媒体选择器、分享入口；逐项评估系统能力、授权与适用性|

## 首个工程里程碑
先交付 v0.1 原生开发预览：五页应用、本地记录/会话/提醒配置、可配置 HTTP 客户端、日历与设备数据适配器、系统每日提醒，以及测试和构建产物。未确认 Hermes 部署前仅称“接口适配待联调”，不称“已经替代飞书”。服务端周期执行与推送属于下个集成里程碑，不能用手机 setInterval 冒充。

## 数据与边界
个人记录与会话保存在应用沙箱，首版限制记录 200 条、会话 100 条，每条最长 4000 字以控制存储量。Token 首版仅驻留进程内存，重启需重填；后续用 Asset Store Kit 保存。禁用备份扩展，避免敏感会话自动备份。删除本地内容不会撤回已发送到 Hermes 的内容。Hermes 使用的模型提供商可能收到上下文，App 中明确提示。

不读取其它 App 私有数据库、聊天记录、屏幕内容。不默认采集位置/健康。读取权限与上传选择分开；选择仅作用于当次发送。日历快照仅在内存保存，刷新获取当天数据，失效后需要重新读取。

## 非功能需求
原生 ArkTS + ArkUI，Stage 模型；沿用现有 API 24 配置，待真机信息确认兼容下限。无第三方 UI 框架。网络超时可解释，禁止无限重试；仅 HTTPS 正式连接，受限的局域网 HTTP 需显式开启。主要触控目标至少 44vp；可滚动页面；系统字体；状态不仅以颜色表达。

## 待用户输入与发布门槛
1. Hermes 仓库/版本和已开启的接口，服务器可达地址（凭据只在本机应用填写）。
2. 手机型号/系统版本，首批数据源的排序。
3. 自用安装或应用市场发行。签名、设备授权、真实网关联调、真机权限及熄屏提醒验收后，才能标记正式发布。
