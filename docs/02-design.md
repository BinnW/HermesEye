## 页面组织
|主入口|当前页面及内容|
|---|---|
|今日|今日计划与状态 → 周期记录提示 → 项目进展 → 最近在读；计划、记录、日报为二级入口|
|项目|项目列表、新建项目、项目目标/下一步/任务/会话；独立需求包含可找回的“漫无目的”|
|阅读|真实进度、授权来源、分批整理状态、逐条疑问与持久回答；历史摘抄/总结另行保留|
|我的|Agent 连接 → 数据来源与授权 → 双 Vault → 提醒与报告 → 持久化显示模式|

所有实际发送从需求会话发生，没有全局聊天。需求来源采用稳定关联，即使重命名或移入项目，原事项入口仍恢复同一历史。项目可建立多个需求。复制另一会话的上下文需逐次选择，显示项目/来源会话及最近六条的范围。

## 表单与状态
- 全局入口“记一笔 / 发起需求”仅在主页面展示。快速记录只需正文，区间、未完成内容、精力自述、决策和新增待办均可选；起止区间必须同时有效。
- 计划按日期保存，待完成/进行中/已完成由用户操作；日历读取与任务完成统计分开。记录新增待办先进入计划表单，经确认才加入。
- 连接名称、IP/域名、协议、端口、路径、模型、遮蔽 Token 和下次连接选项齐全。测试不保存；保存不要求网络成功；保存并连接分阶段反馈。
- 保存成功后清空对应输入；失败保留草稿。表单草稿按服务器留存于当前进程；切换空间不搬运草稿。会话草稿按服务器与需求隔离，列表返回保留滚动位置。
- 本地配置、接口认证、连接、业务同步独立判断。文本接口可用不等于同步完成；未收到远端业务数据时阅读显示“尚未获取”。
- 已收到回复但本地写入失败时，内存保留回复供复制，禁用继续写入，避免自动重复发送。

## 视觉实现
统一使用深浅色语义资源。页面标题 24fp、分区 18fp、正文/按钮 16fp、说明 14fp；卡片 16vp 圆角、输入/按钮 12vp。操作区域至少 48vp。线性图标配短标签，选中同时用文字标记和底色区分。

小于 600vp 使用 16vp 边距；600vp 起 24vp；840vp 起侧栏，正文最大宽约 720vp。输入可增高，正文可完整查看；主题偏好写入本机配置并在启动恢复。实际系统字号、安全区、键盘和屏幕旋转仍需设备验收。

## 目标页面尚未完成的部分
真实微信读书采集与周期实跑、其他模块 IMA 数据链路、AI 计划建议、固定模板自动日报、周期强提醒、健康自动更新、Vault 权限、Coding Agent 运行控制与部署、多端同步冲突仍待外部协议或策略确认。已建立模型与入口的模块不等于其端到端功能已完成。

不采用未确认的精力分值、工作时段或自动部署策略。本机记录汇总明确标为非 AI 分析，说明区间覆盖未知；普通系统每日提醒明确区别于 V1.0 强提醒目标。两份 HTML 草图仅作为设计参考，未用其演示数据填充产品。

## 2026-10-11 · V1 项目与阅读落地

项目沿用 ProjectPanel 的普通详情/表单，补充独立业务服务的显式同步与项目持久会话。阅读由 ReadingPanel 展示业务服务副本，经原子提交缓存到当前空间；范围/周期/分享同意由用户配置，来源及问题结果明确关联。保留原四入口和 V1 色彩，不实现 V2 毛玻璃、胶囊导航或卡片弹层。当前视觉及网络实测边界见 05 与模块 18/20。


## 2026-10-11 · V2 前端实施

主页面四入口改为固定悬浮胶囊；表单与会话隐藏主导航。首页缩短摘要，事项正文打开详情，独立复选框负责完成；日历条目没有完成框。项目概览、里程碑、行动、复盘分区，仅保留一个 Hermes 主入口；归档等生命周期操作收进更多弹层。

阅读采用当前授权来源与百分数进度规格，书籍/疑问详情和周期设置分层展示。连接按地址、凭据、高级选项分组；Token 不出现在摘要。需求会话为 Hermes 左、用户右，消息为实色，输入区固定，附加上下文逐次选择。业务会话的副本与恢复操作收进更多设置。

底栏最大374vp、两侧20vp、底距18vp，内容预留底部滚动空间；基础/深色资源成对，弱模糊和持久实色开关共存。短摘要不替代详情正文，保存失败显示可见反馈并保留草稿。
