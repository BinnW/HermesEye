## 已作出的工程决策
- 单一鸿蒙原生框架，不增加跨端层或 WebView。
- 先建立个人记录与系统上下文的最短闭环；敏感系统数据按需逐项接入。
- 先用保守的非流式聊天接口；长任务与流式进度在确认 Hermes 版本后扩展。
- 客户端系统提醒与服务端智能体定期执行分别建模；不虚构手机后台常驻能力。
- 原型阶段 Token 仅内存；正式私人使用前实现受系统保护的凭据存储。
- 首版统一浅色主题；深色主题、平板双栏和无障碍细化列入视觉验收后续项。

## 需要用户补充的信息
Hermes 项目/版本/接口文档；目标手机型号与系统版本；首批数据来源；自用安装还是应用市场。凭据无需发送到会话，可在应用本机输入。以上影响 M2—M4，不能靠本地模拟测试替代。

## 后续开发顺序
1. 对齐真实协议和兼容 SDK，完成手机签名安装。
2. 运行日历权限拒绝/撤销、熄屏与重启提醒、连续对话测试；修复设备差异。
3. 按真实 Hermes 的任务管理方式实现 SchedulerPort，验证离线执行、结果获取和重复请求。
4. 凭据安全持久化、数据导出/删除、结构化上下文组合模板；按需求扩展数据源。
5. 完成正式隐私说明、安装/升级测试、发行签名与最终发布。
